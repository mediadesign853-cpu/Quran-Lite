# قرآن ریدر لایت | Quran Reader Lite

**زبان‌ها:** [English](README.md) | **فارسی** | [العربية](README.ar.md)

Quran Reader Lite(بدون تفسیر و ترجمه) یک برنامهٔ دسکتاپ ویندوز برای مطالعه و جست‌وجوی متن عربی قرآن، بدون نیاز به اینترنت است. این برنامه با **Electron، React و TypeScript** متن قرآن مبتنی بر جستجوی سریع 

منبع متن قرآن: [پروژهٔ تنزیل](https://tanzil.net) — مجوز CC BY 3.0.

## امکانات اصلی

- مطالعه و جست‌وجوی ۱۱۴ سوره و آیات قرآن.
- نمایش تصاویر ۶۰۴ صفحهٔ مصحف که در نسخهٔ فعلی پروژه قرار دارند.
- ذخیرهٔ نشانک‌ها، تاریخچهٔ جست‌وجو و آخرین محل مطالعه.
- رابط کاربری فارسی و عربی، پوستهٔ روشن و تاریک و امکان تغییر اندازهٔ متن.
- کپی آیات با تنظیم شمارهٔ آیه، قوس‌های قرآنی و نشانی آیه.
- درج پاورقی واقعی در Microsoft Word و Adobe InDesign در ویندوز.
- مطالعه و جست‌وجو به‌صورت آفلاین؛ برای دریافت به‌روزرسانی به اینترنت نیاز است.
- دو نسخه برای ویندوز: نصب‌کنندهٔ NSIS و نسخهٔ Portable.
- به‌روزرسانی خودکار؛ نسخهٔ Portable از فرایند تأیید امضای دیجیتال استفاده می‌کند.

## نصب و راه‌اندازی

۱. وارد صفحهٔ [انتشارهای GitHub](https://github.com/mediadesign853-cpu/quran-lite/releases/latest) شوید.

۲. یکی از این دو فایل را دریافت کنید:

- **Quran Reader Lite Setup** — برنامه را نصب می‌کند و میان‌بر می‌سازد.
- **Quran Reader Lite Portable** — بدون نصب اجرا می‌شود.

۳. در نسخهٔ Portable، پوشهٔ `Quran Reader Lite Data` را کنار فایل EXE نگه دارید. تنظیمات، نشانک‌ها و تاریخچهٔ این نسخه در این پوشه ذخیره می‌شوند. برای به‌روزرسانی، پوشه‌ای که فایل EXE در آن است باید اجازهٔ نوشتن داشته باشد.

**Word و InDesign:** درج پاورقی واقعی فقط در نسخهٔ دسکتاپ ویندوز فعال است. برنامهٔ مقصد (Word یا InDesign) باید نصب باشد و Windows PowerShell 5.1 در دسترس باشد. اگر درج پاورقی انجام نشد، برنامهٔ مقصد را باز کنید و دوباره امتحان کنید.

## ساخت و انتشار نسخه

### پیش‌نیاز و ساخت محلی

برای ساخت برنامه از **Node.js 22** و npm استفاده کنید. در ویندوز و داخل پوشهٔ پروژه این دستورها را اجرا کنید:

```powershell
npm ci
npm run check
npm run dist:win
```

دستور `npm run check` اطلاعات قرآن، نوع‌های TypeScript، قواعد ESLint و ساخت وب را بررسی می‌کند. دستور `npm run dist:win` فایل‌های Electron را آماده کرده و هر دو نسخهٔ ویندوز ۶۴ بیتی را در پوشهٔ `release/` می‌سازد:

- `Quran Reader Lite Setup <version>.exe`
- `Quran Reader Lite Portable <version>.exe`

### کلیدهای به‌روزرسانی Portable و اسکریپت‌ها

سه اسکریپت برای به‌روزرسانی Portable وجود دارد:

| دستور | کاربرد |
| --- | --- |
| `npm run generate:portable-keys` | ساخت جفت کلید Ed25519؛ فقط یک بار هنگام راه‌اندازی سیستم به‌روزرسانی اجرا شود، نه برای هر انتشار. |
| `npm run verify:portable-key` | بررسی وجود و معتبر بودن کلید عمومی Ed25519. |
| `npm run create:portable-manifest` | محاسبهٔ SHA-512 فایل EXE نسخهٔ Portable و ساخت فایل امضاشدهٔ `latest-portable.json`. |

نام دقیق دستور ساخت کلید در این پروژه **`generate:portable-keys`** است؛ دستور `generate:portable` در `package.json` تعریف نشده است.

فایل‌های کلید:

- `electron/portable-update-public.pem` — کلید عمومی؛ این فایل باید در مخزن Git قرار بگیرد.
- `.secrets/portable-update-private.pem` — کلید خصوصی؛ هرگز آن را در Git قرار ندهید یا برای دیگران ارسال نکنید.

محتوای کامل کلید خصوصی را با نام `PORTABLE_UPDATE_PRIVATE_KEY` در بخش Secrets مخزن GitHub ثبت کنید. یک نسخهٔ پشتیبان امن و آفلاین هم نگه دارید. برای هر انتشار کلید جدید نسازید؛ نسخه‌های نصب‌شده به کلید عمومی موجود در برنامه اعتماد می‌کنند.

اسکریپت ساخت Manifest از متغیرهای `PORTABLE_UPDATE_PRIVATE_KEY` و `GITHUB_REF_NAME` استفاده می‌کند. هنگام انتشار، GitHub Actions این مقادیر را تنظیم می‌کند و پس از ساخت فایل Portable، اسکریپت را اجرا می‌کند.

### انتشار با GitHub Actions

فایل گردش‌کار در مسیر `.github/workflows/release-windows.yml` است. این گردش‌کار **فقط با Push کردن یک Tag که با `v` شروع شود** اجرا می‌شود؛ برای مثال `v1.0.1`.

برای هر انتشار:

۱. شمارهٔ نسخه را در `package.json` به نسخهٔ جدید (مثلاً `1.0.1`) تغییر دهید.
۲. فایل Lock را هماهنگ کنید و بررسی‌ها را اجرا کنید:

```powershell
npm install --package-lock-only
npm run check
```

۳. تغییرات انتشار را Commit و به شاخهٔ `main` ارسال کنید؛ سپس Tag با همان شمارهٔ نسخه بسازید و Push کنید:

```powershell
git add package.json package-lock.json
git commit -m "Release v1.0.1"
git push origin main
git tag v1.0.1
git push origin v1.0.1
```

GitHub Actions در محیط ویندوز، Node.js 22 را آماده می‌کند، وابستگی‌ها را با `npm ci` نصب می‌کند، `npm run check` را اجرا می‌کند و هر دو نسخهٔ NSIS و Portable را می‌سازد. سپس Manifest امضاشدهٔ Portable را تولید و بارگذاری می‌کند. انتشار GitHub فقط پس از بارگذاری فایل‌های لازم نهایی می‌شود.

Secret لازم در مخزن: `PORTABLE_UPDATE_PRIVATE_KEY`. گردش‌کار برای بارگذاری فایل‌ها از `GITHUB_TOKEN` خود GitHub استفاده می‌کند.

## نحوهٔ به‌روزرسانی خودکار

- برنامهٔ دسکتاپ ویندوز حدود ۱۵ ثانیه پس از اجرا، به‌روزرسانی را بررسی می‌کند و پس از آن هر ۱۲ ساعت دوباره بررسی می‌کند.
- پیش از دریافت نسخهٔ جدید، از کاربر اجازه می‌گیرد؛ به‌روزرسانی بدون تأیید کاربر نصب نمی‌شود.
- **نسخهٔ نصب‌شده با NSIS:** از `electron-updater` و فایل `latest.yml` در انتشار GitHub استفاده می‌کند.
- **نسخهٔ Portable:** فایل `latest-portable.json` را دریافت و امضای Ed25519 آن را بررسی می‌کند؛ سپس فایل EXE دریافت‌شده با SHA-512 کنترل می‌شود. یک ابزار PowerShell پس از بسته‌شدن برنامه، فایل EXE را جایگزین می‌کند. نسخهٔ قبلی تا زمان اجرای موفق نسخهٔ جدید نگه داشته می‌شود.
- به‌روزرسانی به اینترنت نیاز دارد. پوشهٔ نسخهٔ Portable نیز باید اجازهٔ نوشتن داشته باشد. در صورت ناموفق بودن به‌روزرسانی، نسخهٔ فعلی حفظ می‌شود.

## نکتهٔ امنیتی

تأیید امضای Ed25519 و کنترل SHA-512 از **فرایند به‌روزرسانی نسخهٔ Portable** محافظت می‌کنند؛ این موارد با امضای ناشر ویندوز (Authenticode) یکسان نیستند. فایل‌های EXE فعلی با گواهی Authenticode امضا نشده‌اند؛ بنابراین ممکن است Windows SmartScreen هشدار «ناشر ناشناس» نشان دهد. برنامه را فقط از صفحهٔ رسمی انتشار GitHub که در بالا آمده دریافت کنید.
